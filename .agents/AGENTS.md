# RDS-AES v1.0 (Reisch Development Standard – AI Execution Standard)

## Core Principles
1. **Goal Ownership**: The AI is responsible for reaching the ultimate goal.
2. **Execution Loop**: Goal → Analysis → Planning → Execution → Evaluation → Self-Correction → Validation → Delivery.
3. **Token Efficiency**: Eliminate filler phrases ("I am going to", "Let me", "Next I will"). Use direct analytical structure.
4. **Quality Threshold**: Self-assess work against quality, performance, security, maintainability, readability, and UX criteria (aim for 9+/10 before delivery).
5. **Intelligent Stopping**: Stop when all objectives are met, no further gain is possible, or explicit user input is required.

## DESIGN PRO UI/UX STANDARD
- **Style**: Minimalist Premium (iOS + Material 3), Border radius: 16-24px, Soft shadows, Generous spacing, Smooth animations (200-300ms).
- **Colors**: Primary: `#1F4FD8`, Secondary: `#142E7B`, Background: `#F8FAFC`, Text: `#111827`, Gray: `#6B7280`, Success: `#22C55E`, Warning: `#F59E0B`, Error: `#EF4444`.
- **Typography**: Font: SF Pro Display / Inter. Title: 32px, Subtitle: 24px, Body: 16px, Small: 14px.
- **UX Rules**: Simple navigation, Important actions ≤ 3 clicks, Instant feedback, Dark mode support, Responsive across Mobile/Tablet/Desktop, WCAG Accessibility.

## RDS - Architecture Recovery & Product Refinement Protocol (ARP)
- **Active Defect Discovery**: Active search for defects and hidden issues, not just visible error fixes.
- **No New Features Until Arch Quality Met**: Do not add new features until architecture, scalability, security, and performance reach senior professional standards (9+/10).
- **Phases**: Phase 1 Audit Global → Phase 2 Diagnostic → Phase 3 Plan de correction → Phase 4 Refactoring → Phase 5 Optimisation Produit → Phase 6 Vérification → Phase 7 Validation → Phase 8 Reprise des fonctionnalités.
